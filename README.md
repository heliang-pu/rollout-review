# rollout-review

**English** | [中文](README.zh-CN.md)

Look through the episodes of a [LeRobot](https://github.com/huggingface/lerobot) v2.1 dataset in a browser, one by
one, and judge them by hand. It is for finding dirty data before training: a hand in the picture, an object bumped
halfway through, a wrong label.

- All cameras of an episode are shown in one picture, with the dataset name, the episode number and the task at the
  top left and a frame counter at the top right.
- Three verdicts: ok, problem, unsure; with tags and a note. Everything works from the keyboard.
- The dataset is only read. Nothing is ever written inside it.

Python standard library only (3.10+), nothing to install. Needs `ffmpeg` and `ffprobe` to make the videos.

## Usage

```bash
git clone https://github.com/heliang-pu/rollout-review && cd rollout-review

./rollout-review serve data/real_pick data/real_pour          # open http://127.0.0.1:8790/
./rollout-review serve data/real --host 0.0.0.0 --port 8790   # reachable from a tablet on the same network
./rollout-review stitch data/real --workers 4                 # make all review videos ahead of time
./rollout-review list data/real --verdict problem             # prints e.g. 3,10-12
./rollout-review export data/real > judgements.csv
```

After the review, drop what was judged a problem, for example with
[lerobot-surgery](https://github.com/heliang-pu/lerobot-surgery):

```bash
lerobot-surgery drop data/real data/real_clean \
    --drop "$(./rollout-review list data/real --verdict problem)" --reason "judged a problem in manual review"
```

## Keyboard

| Key | Action |
|---|---|
| 1 / 2 / 3 | ok / problem / unsure (by default the next episode opens right away) |
| 0 | clear the verdict |
| J / K | next / previous episode |
| Space | play or pause |
| ← / → | back or forward one second |

## Where things are kept

Everything goes to `<dataset>_review/` **next to** the dataset, not inside it: lerobot counts every mp4 under a
dataset directory, so one extra file there breaks it.

| File | Content |
|---|---|
| `episode_000012.mp4` | The review video of episode 12 (H.264, plays in any browser). Made when first opened; made again when the source videos are newer |
| `judgements.json` | The current verdicts: episode → verdict, tags, note, data fingerprint, time |
| `judgements.log.jsonl` | Every change, append-only, to trace who decided what when |

## When a verdict goes stale

A verdict is tied to the episode number **and** a fingerprint of that episode's data file. After episodes are
dropped and renumbered, or an episode is recorded again, the same number holds other data, and the old verdict must
not count. The page then shows it as stale; the counts, `list` and the export do not treat it as a verdict.

So the recommended order is: review first, then build a **new** dataset from the verdicts, rather than editing the
reviewed dataset in place.

## Notes

- The page has no login. By default it listens on 127.0.0.1 only. With `--host 0.0.0.0`, everyone on the network can
  watch and change verdicts.
- Up to three cameras are placed in a row, four or more in a grid; each picture is scaled to 480×360.
- The page is in Chinese.

## Tests

```bash
python3 -m pytest -q
```

The tests use small videos generated by ffmpeg and a real HTTP server, and cover the verdict API, stale verdicts and
ranged video requests (needed for seeking in a browser).
